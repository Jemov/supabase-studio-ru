# Supabase Studio на русском

Полный русский перевод интерфейса **Supabase Studio** для самостоятельного размещения. Переведены навигация, таблицы и SQL-редактор, база данных, Auth, Storage, Edge Functions, интеграции, мониторинг, настройки, подсказки, диалоги и штатные сообщения интерфейса. Включены переводы встроенных Monaco, GraphiQL, уведомлений Sonner и элементов Streamdown.

Кириллица использует Inter и Source Code Pro; размеры меню и карточек сохранены близкими к оригиналу. Данные пользователя, SQL, имена таблиц, API-параметры, технические идентификаторы и названия продуктов сохраняются.

Это перевод из исходников: скрипт переводчика в браузере не требуется. Репозиторий содержит полный патч, словари, контрольные суммы и Docker-сборку.

## Сборка Docker-образа

Требуются Git и Docker с Linux-контейнерами. Для сборки выделите Docker примерно **8 ГБ памяти** и не менее **25 ГБ свободного диска**; небольшой рабочий сервер может получить уже собранный образ с другого компьютера. Во время сборки нужен доступ к GitHub, npm и Google Fonts. Ключи Supabase и пароль базы для сборки не нужны.

```sh
git clone https://github.com/Jemov/supabase-studio-ru.git
cd supabase-studio-ru
docker build --build-arg STUDIO_PUBLIC_URL=https://supabase.example.com --tag supabase-studio-ru:7996410 .
```

Укажите свой внешний адрес Studio вместо `https://supabase.example.com`: только протокол, домен и при необходимости порт, без пути или завершающего `/`. Если не передать аргумент, используется `http://localhost:3000`.

Команды одинаковы для Linux/macOS и PowerShell на Windows. Dockerfile получает точный исходный коммит, проверяет и применяет полный патч, устанавливает зависимости из lockfile, переводит их по проверенным контрольным суммам и собирает Next.js standalone. В сборку включается WASM SQL-парсера; проверяется выполнение разбора `SELECT 1`.

Сборка создает локальный образ. Готовый образ или пакет в контейнерном реестре этим репозиторием пока не публикуется.

## Установка в существующий Supabase

В существующей установке Supabase найдите основной `docker-compose.yml`. Сохраните прежнее имя образа сервиса `studio`, чтобы можно было вернуться к нему. Скопируйте рядом [examples/docker-compose.ru.yml](examples/docker-compose.ru.yml).

Если собирали образ на другом компьютере, перенесите его на сервер:

```sh
docker save --output studio-ru.tar supabase-studio-ru:7996410
scp studio-ru.tar user@your-server:/tmp/studio-ru.tar
```

На сервере:

```sh
docker load --input /tmp/studio-ru.tar
```

Из каталога существующей установки выполните:

```sh
docker compose -f docker-compose.yml -f docker-compose.ru.yml up -d --no-deps studio
docker compose -f docker-compose.yml -f docker-compose.ru.yml ps studio
docker compose -f docker-compose.yml -f docker-compose.ru.yml logs --tail=100 studio
```

Если установка использует дополнительные Compose-файлы, включите их в команду перед русским override. В результате меняется только образ Studio, а окружение, сети, подключения к БД и остальные сервисы наследуются из вашей конфигурации. Пересоздается только контейнер `studio`. После запуска откройте Studio и обновите страницу с очисткой кеша (`Ctrl+F5`).

Если у вас другая версия Studio, сначала проверьте совместимость на тестовой установке. Не запускайте отдельный новый стек Supabase ради перевода существующей базы.

## Откат

Запустите Studio с прежними Compose-файлами, исключив русский override:

```sh
docker compose -f docker-compose.yml up -d --no-deps studio
```

При наличии других обычных override-файлов сохраните их в команде. Если ранее изменяли основной файл напрямую, верните сохраненное имя образа Studio. Данные БД не изменяются установкой или откатом интерфейса.

## Работа с исходниками

Для проверки пакета нужен Node.js 22:

```sh
node scripts/verify.mjs
node scripts/prepare-source.mjs
node scripts/verify-source.mjs
```

`prepare-source.mjs` создает **новый** каталог `upstream/`, получает исходный коммит и применяет патч в индекс Git. Уже существующий каталог скрипт не перезаписывает. Проверка сравнивает итоговый индекс с полным опубликованным патчем.

- [patches/studio-ru.patch](patches/studio-ru.patch) — полный итоговый перевод исходников, включая шрифты, локальные ассеты и вспомогательные функции отображения.
- [patches/dependency-locales.json](patches/dependency-locales.json) — точные переводы 30 файлов установленных зависимостей: версии, диапазоны исходного текста и контрольные суммы до/после.
- [translations/](translations/) — вспомогательные словари. Итоговые исправления и контекстные переводы находятся в полном патче; одних словарей для воспроизведения перевода недостаточно.
- [manifest.json](manifest.json) — версии и SHA-256 опубликованных материалов.
- [docs/validation.md](docs/validation.md) — результаты проверки переведенной сборки и отдельные проверки публикационного пакета.

Для изменения перевода редактируйте исходники из точного коммита, формируйте новый полный патч и обновляйте manifest. Для зависимостей пересчитывайте контрольные суммы после изменения переводов. После перехода на новую версию повторно проверяйте диапазоны и исходные тексты: скрипт намеренно прекращает работу при их несовпадении.
